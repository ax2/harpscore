# HarpScore

跨平台的**布鲁斯口琴（十孔口琴）乐谱软件**——琴谱展示、管理与导出。开源，MIT 协议。

![License](https://img.shields.io/badge/license-MIT-blue)

## 功能

- **专业琴谱展示**：上行简谱（数字 + 八度点 + 升降号 + 附点 + 节奏下划线 + 延音线 + 歌词），下行口琴演奏标记（吹吸方向 + 孔号 + 压音级别 + 超吹 + 技巧），小节线 / 反复记号 / 双纵线完整刻画
- **吹吸配色**：`+N` 吹气（暖红）、`-N` 吸气（深蓝）、`'` 压音（每个符号半音）、`°` 超吹、`~` 振音
- **曲谱管理**：内置曲谱 + 个人曲谱（浏览器本地持久化），多词搜索、难度/标签/压音筛选、排序、本地收藏、删除、JSON 导入
- **导出**：PNG（高清位图）、SVG（矢量）、打印 / PDF、JSON 源文件
- **可吹性分析**：按指定标准 Richter 调性自动标注孔位，统计音域、压音数量，超出当前口琴能力的音即时提示（不含 Low/High 特殊型号）
- **手机阅读**：按可用宽度自动重新分行，保留长音、多八度点和跨行延音；导出使用完整页面布局
- **变拍曲谱**：支持小节级拍号变化，自动沿用后续小节的拍号；谱面及 JSON / SVG 导出保留变拍记号
- **前倚音**：支持 1–4 个短倚音的小号谱面与孔位，音域、可吹性和筛选均计入倚音；倚音不增加小节拍数
- **单顺／逆波音**：显式保存邻音，校验相邻音级、指法和音域；谱下的“辅”标出辅助音孔位
- **三十二分音符**：支持短音与附点时值、三道减时线；密集小节按拍点续行，虚线与“续”字表示同一小节
- **显式弱起与延长记号**：允许来源明确的短首节搭配足拍末节；自由延长记号保留书面时值和谱面提示
- **跨平台**：纯 Web 应用，浏览器即开即用，桌面 / 手机 / 平板通用（PWA 友好）

## 本地开发

打印 / PDF 使用 A4 纵向整行分页，续页重复曲名、调号和图例；跨页延音保留，主孔位字号约 8.5 pt。导出时建议保留 A4 纵向设置。普通 SVG/PNG 仍为完整长图。验证记录见 [Stage 6 打印与把位校正](docs/stages/stage-6-print.md)。

```bash
npm install
npm run dev      # 开发服务器
npm run build    # 产出 dist/
npm run preview  # 预览构建结果
npm test         # 导入器自动化测试
npm run scores:validate # 校验全部内置谱
```

开发环境要求 Node.js 20.19+ 或 22.12+（Vite 8 要求）。

## 曲谱数据格式

完整 JSON 的 `techniques` 可包含 `vibrato`（振音）、`bend-release`（压音释放）、`slap`（舌拍）、`gliss`（滑音）、`trill`（颤音）。这些是文字提示，不包含交替音、过程音或和声音的完整信息；谱面和导出会保留标记，并提示需要核对的音高。分析中的“已记音高均有孔位”仅说明谱中明确音高的定位结果，节拍与技巧提示仍需检查。详见 [技巧验证](docs/stages/stage-6-techniques.md)。

个人曲谱保存在当前浏览器。曲库侧栏的「备份个人曲库」可下载完整原始数据；「恢复个人曲库」支持上传备份数组，整批检查后合并或替换。替换需确认，并先保存最近一份恢复前副本，可从恢复窗口导出；副本保存失败或检测到其他标签页修改时取消替换。收藏列表独立于曲谱备份；支持 Web Locks 的浏览器会协调多标签页收藏写入并同步显示，损坏收藏数据不会被普通操作覆盖。其他标签页修改后可点击「重新读取曲库」。导入同 ID 曲谱保留两首；损坏库会阻止普通导入/删除，仍可查看有效条目、导出原文，或用有效备份替换。详见 [存储验证](docs/stages/stage-6-storage.md) 和 [备份恢复](docs/stages/stage-6-restore.md)。

曲谱为 JSON（见 `src/data/scores/*.json`）：既可导入包含 `lines` 的完整 HarpScore JSON，也可导入包含 `melody` 的旋律 DSL JSON。导入器会校验嵌套结构、规范化八度、避免 ID 覆盖，并重新推算口琴孔位。

导入窗口支持 Tab 循环、Escape 关闭及焦点返回；读取文件期间显示进度并暂停提交，过期读取不会覆盖新草稿。短横屏可滚动访问按钮。详见 [导入交互验证](docs/stages/stage-6-import.md)。

批量制谱使用配套导入工具：`tools/import/*.json` 为旋律 DSL 输入（空格分词、`|` 小节线、`/` 八分、`//` 十六分、`///` 三十二分、`'` 高音点、`,` 低音点、`#`/`b` 升降、`~` 延音、`=字` 歌词、`-` 延长一拍），运行 `npm run scores:build` 完成“深层校验 → 八度规范化 → 可吹性验证 → 孔位推算 → 写入内置曲谱 → 重建索引”全流程。

三十二分音符在完整 JSON 中使用 `beats: 0.125`。如 `3//. 5///` 为附点十六分加三十二分，合计半个四分拍；64 分音符与 32 分形状的倚音暂不支持。手机阅读时过密小节会续行，虚线不是小节线，拍数与临时升降号沿用；数据及宽版导出不增加实际小节。

非原创内置谱优先以文字简谱或清晰数字简谱逐音核对，并记录 `sourceUrl`、`sourceFormat` 与 `sourceCheckedAt`；五线谱不作为图片识别输入。`npm run scores:validate` 会同时阻止节拍、可吹性或来源字段不完整的曲谱进入发布。

可追踪的 ABC / LilyPond 音符文本采用独立的 `music-text` 来源类型，保留版本、转调和反复处理说明。小节变拍在 DSL 中写为 `[M:3/4] 1 2 3`（记号必须位于小节开头）；完整 JSON 在小节对象中使用 `timeSignature`。该拍号持续生效，直到下一次变拍。变拍曲暂不自动豁免首尾弱起，请检查其节拍提示。

数据中的临时升降号逐音指定，不隐式沿用前一音：例如 `#4 4` 表示升 fa 后还原为自然 fa，谱面会自动补出还原号。同一小节内若需连续升 fa，写作 `#4 #4`。

前倚音写在主音前的花括号里，如 `{5}4/` 或 `{6,;1'}2`，分号分隔，最多 4 个。默认显示十六分小音符，`{5/}4` 显示八分小音符；完整 JSON 用主音的 `graceNotes` 数组，每项 `beats` 只能是 `0.25` 或 `0.5`。该值表示符形，不作为独立拍数相加；实际演奏需快速连入主音。倚音不能为休止、嵌套，或携带歌词、附点、延音、技巧。当前不支持把延音线跨过另一音的前倚音。

单顺波音写作 `[U:3']2'/`，表示高音 re 的八分音符，快速奏 re–mi–re；逆波音 `[L:1]2` 表示 re–do–re。方括号内只写邻音音高，必须是正确方向的相邻音级，可以显式带升降号。完整 JSON 示例：`"ornament": {"kind": "upper-mordent", "auxiliary": {"degree": 3, "octave": 1}}`。辅助音没有独立时值，分析总数中单独注明其数量，不把返回主音重复计数；谱下“辅 +8”意为辅助音吹 8 孔。当前单波音不与同一主音的倚音/其他技巧叠加，不支持延音跨入波音，也不等于已实现 tr 颤音、复波音或回音。

显式弱起：在顶层 JSON 声明 `"pickupBeats": 1`，以四分音符为一拍。数值须大于零、小于首小节有效拍号的时长，并与首小节实际音符时长完全一致；弱起后至少有一个小节。它只放行首小节，不掩盖中间或末尾缺拍，适用于《红河谷》这类末小节足拍的版本。未声明时仍沿用原有首尾互补识别。

延长记号：DSL 写 `3!`、`0!` 或 `{6,/}3!`；同音延音同时存在时写 `3!~`。完整 JSON 使用音符的 `fermata: true`。半圆加点表示按乐句自由延长，不自动加拍，不承诺固定播放时值；倚音和波音辅助音上不接受该属性。
