# Stage 6：个人曲库完整性修复

2026-10-23，北京时间。Stage 6 整体验收中的第一批修复，未发布。

## 已复现的问题

旧版本四项针对性测试全部失败：连续导入使旧曲谱孔位消失；损坏存储被当作空库覆盖；过期标签页导入同 ID 覆盖先前曲谱；保存时间在重载时丢失。其原因分别是重新解析后的旧曲谱未分析、读取异常被吞掉、新增使用替换语义、导入器未保留 updatedAt。

## 实现

- 所有加载、导入和删除返回的个人曲谱都重新计算孔位，技巧筛选与谱面保持一致。
- 导入只追加。保存时读取最新库、分配唯一 ID，返回实际保存的曲谱供界面选择；64 字符 ID 留出后缀空间，避免重载截断又发生碰撞。
- 旧数据中的重复 ID 或与内置谱相同的 ID，在视图中分配独立 ID；下一次正常保存持久化修复，不混淆删除对象。
- 支持 Web Locks 的浏览器使用同源锁串行化导入与删除。删除还要求原始存储快照一致，过期页面需先重新读取。
- 无法解析、根结构错误、部分条目无效或存储不可读时，禁止保存/删除；仍能打开有效条目。原始内容通过「备份个人曲库」逐字导出，「重新读取曲库」可读取外部修复或其他标签页的修改。
- 写入失败保留导入弹窗和输入，不修改调用者数据；写入期间禁用重复提交。updatedAt 经完整 JSON 再导入和重载仍保留。

## 验证

- 85 项测试通过，含新增 8 项存储回归；44 项内置谱节拍、延音、来源和音高门禁通过；生产构建通过。
- Chromium 真实界面：连续导入与自然音/压音筛选、删除后指法、两个标签页同时导入同 ID、过期删除拦截、重新读取、部分损坏数据保护、原文备份、配额失败保留输入均通过。
- 桌面 1440×1000、移动尺寸 390×844 截图已检查：损坏提示可读，备份/重新读取按钮可从移动曲库抽屉访问；移动备份文件也逐字对比通过。
- 备份原文为测试夹具，不含真实个人曲谱。截图和浏览器结果位于本任务 outputs/stage-6-storage，副本同步到技术博客档案。

## 限制与后续

- 不支持 Web Locks 的旧浏览器或非安全上下文退化为同步读写，不能保证多个窗口同时写入的原子性；同源旧版应用也不受新锁约束。
- 原始曲库备份目前是保全/人工修复文件；现有单曲导入不能直接恢复多曲数组。后续应增加经过预检、一次写入的批量恢复流程，不能把下载备份等同于已验证完整恢复。
- 尚未完成技巧标记、把位说明与长谱打印的整体验证；85 测试不代表所有音乐版本、实体口琴及真实手机验收完成。
