# Stage 8 内置曲库传输

60项曲库的3358个音符仅有203种完整记录。原生产主JS为544,314字节，超过默认500kB建议值；其中大量重复的孔位、时值、音高及默认字段会被重复解析。

构建工具仍按原流程生成和验证完整 `src/data/scores/*.json`，另将完整音符按JSON值去重，生成 `builtin.packed.json`。运行时的 `builtin.ts` 只导入该传输数据，并还原标准 `Score[]`。来源说明、音高、时值、反复、装饰音、歌词、派生孔位、字段是否存在等均保留。公开导入、导出、个人曲库和备份格式不变，不引入网络延迟加载或新的依赖。

每次展开都独立复制曲谱元数据、音符及嵌套倚音/波音对象，避免后续指法分析原地更新时串改别的音符或曲谱。构建内部版本及字典索引异常时明确失败，不能默默替换音符。

验证包含全库完整JSON深层等价、来源DSL重建一致性、可重复生成，以及跨曲谱/重复音符/多次展开的可变对象隔离。两内核生产构建中实际逐首导出60份JSON，与完整文件逐项相等；另往返导入包含倚音、波音、变拍与延长的三曲。

生产主JS减至294,293字节，减少45.93%；Vite构建报告的gzip约93.62kB→87.94kB。未改500kB阈值，原建议警告消失。体积缩小不等于启动时延必然缩短：运行时增加了字典展开和对象复制。本机各5轮冷上下文观察中，Chromium曲库就绪中位数约130→140ms、Firefox约192→192ms；测试期间存在其他自动测试负载，不能将这些小样本当作移动设备或真实网络性能结论。

音乐内容没有因本轮修改而重新选版；曲库仍为56歌曲与4原创练习，专业审校和实体演奏边界沿用来源台账。
