# Stage 6：个人曲库备份恢复

2026-10-23，北京时间。补齐上一批原始备份只能人工处理的缺口。

## 使用流程

曲库侧栏选择「恢复个人曲库」，上传下载的备份 JSON 或粘贴数组。界面先列出可读取曲谱、错误条目和记谱提示。任何条目结构错误都会阻止整批恢复，不部分写入。

- 默认合并：读取最新个人曲库，保留现有曲谱。同 ID 曲谱分配新 ID，两首都保留。
- 可选替换：确认后完整替换个人曲库，可用于修复损坏数据。替换前先把当前原始数据保存到恢复副本，副本写入失败就取消替换；检测到其他标签页修改时要求重新读取确认。内置曲谱不参与替换。
- 「导出恢复前副本」下载最近一次替换前的原始数据。副本只保留一代，再次替换会更新它；需要长期保留的副本应下载到本地。损坏的副本仍保留原文，需要修复错误后才能恢复。
- 空数组仅允许在明确选择替换并确认后还原为空库；合并空备份不可执行。

## 实现与数据边界

恢复和单曲导入共用同源 Web Lock。所有备份条目先经过同一曲谱导入校验，再一次写入最终库；派生孔位重新分析，已有 updatedAt 保留。恢复前副本保存原始字符串，不经过曲谱规范化。当前库写入失败时旧值保持不变，副本可能已成功保存，界面不会报告恢复成功。

备份仅包含个人曲谱；收藏列表不包含在备份中，恢复时保留当前收藏列表。恢复并非原始 JSON 字段顺序或格式的保真编辑，支持的曲谱字段经过正常导入校验。结构合法但节拍/延音存在问题的曲谱会显示记谱提示，不能把“可读取”理解为旋律已经来源核对。
